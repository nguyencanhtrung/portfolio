## 1. Overview

The lifting factor $$Z_c$$ — also written $$Z$$, and sometimes called the
expansion factor — decides how many times the base matrix $$B$$ is expanded to
produce the parity check matrix actually used for encoding and decoding.

Describing a parity check matrix through a [base matrix](/blog/ldpc-base-matrix/)
is what makes 5G LDPC implementable. Each entry of $$B$$ stands for a
$$Z_c \times Z_c$$ block, so storing $$B$$ instead of $$H$$ saves a factor of
$$Z_c^2$$ in memory. In practice the saving is larger still, because the
computation only ever touches parts of the base matrix — the $$A$$, $$E$$,
$$C_1$$ and $$C_2$$ sub-matrices.

The rest of this post follows how 3GPP defines $$Z_c$$.

***

## 2. Computing $$Z_c$$

![](/images/blog/ldpc-lifting-factor/2.png)

Each lifting set index $$i_{LS}$$ carries several possible values of $$Z_c$$.
They are generated from two parameters:

| Parameter | | | | | | | | |
|:-----:|:-:|:-:|:-:|:-:|:-:|:-:|:-:|:-:|
| $$i_{LS}$$ | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| $$a$$ | 2 | 3 | 5 | 7 | 9 | 11 | 13 | 15 |
| $$J_a$$ | 7 | 7 | 6 | 5 | 5 | 5 | 4 | 4 |

Read the table like this:

* for index 0, where $$a = 2$$, the exponent runs $$j_a = 0, 1, 2, \dots, 7$$
* for index 2, where $$a = 5$$, it runs $$j_a = 0, 1, 2, \dots, 6$$

and so on. For each value of $$a$$ — equivalently, for each $$i_{LS}$$ — the
legal lifting sizes are

$$
Z_c = a \cdot 2^{j_a}
$$

So table 5.3.2-1 in the specification is not an arbitrary list. It is the set of
values $$a \cdot 2^{j_a}$$ grouped by $$a$$, which is why every legal $$Z_c$$ is
a small odd number times a power of two. That structure is deliberate: it lets
the shift network in a decoder be built from a fixed radix rather than a general
barrel shifter.

In the end only the $$Z_c$$ values themselves matter to an implementation; the
index $$i_{LS}$$ matters because it selects which column of shift coefficients
the base matrix uses.

***

## 3. Selecting $$Z_c$$

The choice depends on the **length of the information block** to be encoded, in
bits. The rule is: take the smallest legal $$Z_c$$ that is still big enough to
hold the payload, given how many base-matrix columns carry information.

Once $$Z_c$$ is fixed, the base matrix $$B$$ is constrained as follows:

* Entries take values in $$[-1, 0, \dots, Z_c - 1]$$.
* Every entry expands to a $$Z_c \times Z_c$$ block.
* `-1` expands to the all-zero matrix.
* `0` expands to the identity matrix.
* A value $$a > 0$$ expands to the identity matrix cyclically shifted right by
  $$a$$ positions.

That last rule is the reason the whole scheme is cheap in hardware: every
non-zero block is a rotation of the identity, so a block-row operation is a
rotate plus an accumulate, never a general matrix multiply.

***

## 4. Matlab code

```matlab
% Find the minimum value of Z in all sets of lifting sizes in 38.212
%  Table 5.3.2-1, denoted as Zc, such that Kb*Zc >= Kd
%  Step 1: determine Kb
%  Step 2: determine the minimum value of Zc

% Kb is the number of columns carrying actual information bits
% (no filler bits) in the base matrix
if NBG == 1
    Kb = 22;
else
    if B > 640
        Kb = 10;
    elseif B > 560
        Kb = 9;
    elseif B > 192
        Kb = 8;
    else
        Kb = 6;
    end
end

Zlist = [2:16 18:2:32 36:4:64 72:8:112 120 128 144 160:16:256 288 320 352 384];

% Kd is the length of each code block (excluding filler bits)
for Zc = Zlist
    if Kb*Zc >= Kd
        break;
    end
end
```

Two details worth noting in that loop. `Zlist` is exactly the set generated by
$$a \cdot 2^{j_a}$$ in section 2, written out in ascending order — which is why
the first value that satisfies the inequality is also the smallest legal one.
And `Kb` depends on the base graph and, for base graph 2, on the transport block
size: fewer information columns means a larger $$Z_c$$ is needed to carry the
same payload.
